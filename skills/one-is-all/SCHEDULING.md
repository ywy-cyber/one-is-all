# 调度清单（哪类活怎么安排）

主控每接一件事，先按这张表分流。**判错的代价是要么自己累死，要么派出去的东西验收不了。**

---

## 0. 先问三句

1. **能不能 3 轮工具调用内做完？** 能 → 自己做（A/B 类）。
2. **要不要改多个文件、跑长命令、连集群？** 要 → 派单（C 类起）。
3. **是不是不可逆或对外？** 是 → 只能呈报，批准后再派单执行（I 类）。

拿不准往「派单」那边靠。

---

## 1. 分流表

| 类 | 什么活 | 谁做 | 预算 | 交付物 | 登记 |
|---|---|---|---|---|---|
| **A** | 一次性只读查询：某个值、某一行、装没装 | 主控自己做 | ≤3 轮 | 一句话 + 出处 | 否 |
| **B** | 小改动：单文件、单点、不跑长验证 | 主控自己做 | ≤3 轮 | 改了什么 + 1 例自测 | 否 |
| **C** | 实现 / 修复：跨文件、要跑测试 | 成员 1 个 | 1~2h | diff + 自测证据 | 是 |
| **D** | 调查 / 现状核对：要翻多个文件或跑状态命令 | 成员 1 个 | 30~60min | 现状 + 证据 + 未决 | 是 |
| **E** | 长任务：训练 / 评测 / 搬数据 / 集群作业 | 成员 1 个（或后台） | 作业×1.5 + 1h | 作业 ID + 日志 + 指标 | 是（带截止） |
| **F** | 外部调研：网页、文档、方案对比 | 成员 1 个 | 30min | 2~3 个方案 + 对比表 + 来源（取舍由主控做） | 是 |
| **G** | 写作 / 文档 | 成员 1 个 | 1h | 文件路径 + 变更摘要 | 是 |
| **H** | 独立复核：验收高风险产物 | 另派 1 个成员（不能是作者） | 20min | 通过 / 不通过 / 证据不足 + 依据 | 是 |
| **I** | 不可逆 / 对外：删除、推送、发版、改远端 | 主控先呈报；批准后成员执行 | 按单 | 操作记录 + 回滚方案 | 是 |
| **J** | 并行：≥2 个互不依赖方向 | 一次派 2 个（最多 3） | 各自按类型 | 各自交付物 | 是 |

---

## 2. 每类的具体要求

### A. 一次性只读查询

- 例：某文件第 5 行、`oia` 版本、某个环境变量。
- 一次 `read` / `exp` 能答的，不要派单。
- 超过 3 次调用还没答出来 → 转 D。

### B. 小改动

- 例：改一个配置值、修一个 typo、加一个参数。
- 只 `read` + `edit`；改完做 **1 例最小测试**。
- 要跑测试脚本 / 多条命令 → 转 C，别硬撑。

### C. 实现 / 修复

工单七样：目标、交付物、验收口径、范围、输入、颗粒度、预算。
范围写清「只能写哪些文件」；验收口径写「跑什么、看到什么算过」。

### D. 调查 / 现状核对

- 工单写「只读」；禁止改文件、起停服务、提交。
- 回执必须带：结论、证据（命令 + 输出 / 文件行号）、未决、下一步。
- 同一件事**不要同时派两个**（会得到两份口径）。

### E. 长任务

- 截止时间必填：作业预计 ×1.5 + 1 小时。
- 派单后挂 `watch`；不要轮询。
- 回执里必须有作业 ID；没有 ID 不算交付。

### F. 外部调研

- 工单写「至少 2 个方案 + 取舍 + 来源链接」。
- 调研结论由主控裁决，成员不给结论只给对比。

### G. 写作

- 写清读者是谁、放哪个文件、要不要更新 README。
- 交付物是文件路径，不是聊天里的一段话。

### H. 独立复核

- 高风险（删数据、发版、对外）必须复核。
- 复核者不能是作者；复核只看证据与验收口径，不重做。
- 复核结论三种：通过 / 不通过（写清哪条）/ 证据不足（要什么）。

### I. 不可逆 / 对外

- 主控只能呈报：现状一句 → 选项 A/B → 建议 → 不选的后果。
- **批准后**，派单文本里必须带 `[APPROVED]`，否则扩展直接拦（破坏性派单闸）。
- 用户原话已经明确说「删掉这个文件」时，视为已批准，可直接带标记。
- 执行完必须给：操作记录、影响范围、回滚办法。

### J. 并行

- 一次最多派 3 单；同时 running 不超过 5。
- 两个方向必须真独立（不读同一批文件、不抢同一个资源）。
- 有依赖就串行：前一个 DONE 再派后一个。

---

## 3. 记账只三步

```
oia add --title … --owner one-is-all-member --state running
oia set <ID> --ref <runId>
oia archive <ID> --artifact … --verdict …
```

- 不要 `show` / `validate`；`board` 一轮最多一次。
- **没登记就派单 = 这轮不合格。**
- 归档时写一句人话结论，别写「已完成」。

---

## 4. 主控自己的边界

- 5 个 assistant turn 内能做完的，自己做；到第 6 轮还没结果，停手转派单（扩展会拦）。
- 派单后 0 次工具调用（查状态除外）；回执没回来就写「执行中」。

- 一轮最多派 3 单。

---

## 5. 反例（别这么干）

- 一句「某工程什么状态」自己读 README + devlog + 跑 status —— 这是 D 类，派单。
- 派完单自己又去读项目文件 —— 两份口径，必错。
- 调查单里顺手改了两行 —— 越界，回执会被打回。
- 长任务不写截止时间 —— 主控没法判断该不该收尾。
- 高风险任务自己验自己 —— 复核必须是另一个人。

## 6. 派单模板（按类下达，不要千篇一律）

### C 实现 / 修复

```
[DISPATCH T03]
目标: …
交付物: diff + 自测输出
验收口径: 跑 `…`，看到 …
范围: 读 … / 写 …
输入: …
颗粒度: 处方级
预算: 2 小时
```

### D 调查 / 现状核对

```
[DISPATCH T03]
目标: 只读核对 …… 的现状
交付物: 现状 + 证据 + 未决
验收口径: 每个结论都有命令输出或文件行号支撑
范围: 只读；不写文件、不起停服务、不提交
颗粒度: 方向级
预算: 45 分钟
```

### E 长任务

```
[DISPATCH T03]
目标: 提交并盯完 ……
交付物: 作业 ID + 日志路径 + 最终指标
验收口径: 作业 ID 存在，终态为 succeeded/failed 且有出处
范围: 只能经 <CLI> 提交，不改代码
预算: 作业预计 × 1.5
截止: <时间>
```

### F 外部调研

```
[DISPATCH T03]
目标: 对比 …… 的 2~3 个方案
交付物: 方案表（做法 / 代价 / 风险 / 来源）
验收口径: 每个方案有来源链接，取舍有理由
范围: 只读网页与文档
预算: 30 分钟
```

### G 写作 / 文档

```
[DISPATCH T03]
目标: 写 ……（读者：……）
交付物: <文件路径> + 变更摘要
验收口径: 文件存在，覆盖约定章节
范围: 只写 <文件/目录>
预算: 1 小时
```

### H 独立复核

```
[DISPATCH T03]
目标: 独立复核 T02 的产物
交付物: 通过 / 不通过（写清哪条）/ 证据不足（要什么）
验收口径: 只看证据与验收口径，不重做、不看作者结论
范围: 只读
预算: 20 分钟
```

### I 不可逆 / 对外

```
先呈报：现状一句 → 选项 A/B → 建议 → 不选的后果
批准后：
[DISPATCH T03]
目标: 执行 ……
交付物: 操作记录 + 影响范围 + 回滚办法
验收口径: 每一步有命令与输出；回滚办法可执行
预算: 按单
```
