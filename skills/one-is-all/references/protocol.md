# one-is-all 交互标准（v1）

形式规范：角色、状态机、消息、时序、巡检、闹钟、失败码。
行为纪律在 `LEADER.md` 与 `WORKER.md`，表的操作在 `references/board.md`。

---

## 1. 角色与不变量

| 角色 | 数量 | 对谁负责 | 能写什么 |
|---|---|---|---|
| 用户（human） | 1 | — | 任何东西；只有他能改目标与授权不可逆动作 |
| 主控（leader） | 1 | 用户的原话 | 任务总表、`intent` |
| 负责人（owner） | ≤5 个 `running` | 一张工单 | 工单范围内的文件、自己的 `reports/<ID>.md` |

不变量：

1. **单一窗口**：用户只与主控对话；负责人不直接接触用户。
2. **单一真相**：任务状态只存在于 `board.md`；口头汇报不算记录。
3. **单一写者**：只有主控写表；负责人只写自己的回执。
4. **不嵌套**：负责人不得再派 subagent。
5. **不阻塞**：主控任何一轮都能在十几秒内结束；长活永远在负责人或后台。
6. **先证据后结论**：任何 `DONE` 必须带可复现证据，否则不算完成。

## 2. 任务状态机

```
            add            start
  queued ─────────► running ──────► running(节拍运行中)
     │                │  ▲
     │                │  └── status running（恢复）
     │                ├── waiting_you（只有用户能解）
     │                ├── blocked（等外部，降频 900s）
     │                ├── review（已交，待主控验收）
     │                │      ├── 通过 → archive
     │                │      └── 返修 → running（≤2 次）
     │                └── paused / dropped
     └──────────────► dropped
```

| 状态 | 是否巡检 | 含义 |
|---|---|---|
| `queued` | 否 | 已登记，等 slot（同时 running ≤5） |
| `running` | 是 | 有负责人在干 |
| `waiting_you` | **否** | 只有用户能解开（目标/取舍/授权） |
| `blocked` | 是（≥900s） | 外部原因卡住，主控在解 |
| `review` | **否** | 负责人已交，等主控验收 |
| `paused` / `dropped` | 否 | 暂停 / 取消 |
| `done`（归档） | **否** | 已验收，只读 |

跃迁规则：

- `queued → running`：`oia start <ID>`，节拍重置为 30s、连检 0。
- `running → waiting_you|review|paused`：`下次巡检` 置 `-`，**立即停止巡检**。
- `running → blocked`：节拍取 `max(当前, 900)`，连检清零。
- `review → running`：返修，按新派单重置 30s；同一任务返修 ≤2 次。
- 任意 → `dropped`：主控或用户取消。
- `running|review → done`：只能由主控 `oia archive` 产生。

## 3. 节拍状态机

每任务独立。档位与升级条件：

| 档位 | 升到下一档需要 | 下一档 |
|---|---|---|
| 30s | 连续 3 次 tick 无异常 | 60s |
| 60s | 连续 5 次 tick 无异常 | 300s |
| 300s | 连续 3 次 tick 无异常 | 900s |
| 900s+ | 不再自动升 | 主控可 `oia set --interval` 自定义 |

降级：任何一次 `--anomaly` → 30s，连检清零。

「异常」只有五种：

1. 收到 `BLOCKED`
2. 收到 `DONE`（待验收）
3. 超过 2 个节拍没有回执
4. `list_agents` 里负责人不存在
5. 返修

`next_check = last_check + interval`，由 `oia tick` 维护。
`last_seen`（最后回执）是判断"沉默"的依据，不是 `last_check`。

## 4. 消息定义

### 4.1 主控 → 负责人（五类）

| 类型 | 触发 | 是否等回复 | 必填 |
|---|---|---|---|
| `DISPATCH` | 新任务 | 否 | 目标、交付物、验收口径、范围、输入、颗粒度、预算 |
| `QUERY` | 巡检异常 / 用户问细节 | 否 | 「需要确认的现状」条目 |
| `ADJUST` | 用户改需求 / 主控调范围 | 否 | 「需要调整的方向」条目 |
| `APPROVE` | 用户或主控放行 | 否 | 「批准的进一步执行」条目 |
| `STOP` | 暂停/取消 | 否 | 原因一句；优先发「收尾令」，再 `STOP` |

格式（`DISPATCH` 示例）：

```
[DISPATCH T03]
目标: 把 cap5 三个分片跑完并出汇总
交付物: reports/cap5-summary.md
验收口径: 三分片都有数；总数与清单一致
范围: 读 data/cap5/**；写 reports/**
输入: data/cap5/shards.json
```

三类短指令的正文只能列条目，不得夹带叙事：

```
[QUERY T03]
需要确认的现状:
  - 迁移脚本跑没跑通，失败几条

[ADJUST T03]
需要调整的方向:
  - 先只迁 cap5，其他不动

[APPROVE T03]
批准的进一步执行:
  - 可以跑全量
```

### 4.2 负责人 → 主控（四类）

| 类型 | 触发 | 必填 |
|---|---|---|
| `STATUS` | 被 `QUERY` | 四段 |
| `DONE` | 完成 | 四段 + 验收口径逐条对照 |
| `BLOCKED` | 卡住 | 卡点、试过什么、A/B、建议 |
| `DECIDE` | 需决策 | 问题、A/B、影响、建议 |

四段格式：

```
结论: 1~3 句
证据: 路径:行 / 命令 / 关键输出（≤5 行）
未决: ≤3 条，每条带建议
下一步: 一句话
```

字数上限：`STATUS` ≤12 行，`DONE` ≤20 行，`BLOCKED`/`DECIDE` ≤10 行。

## 4.3 终止权

宿主可能给子 agent 设运行超时，那只是安全绳。**是否终止由主控按预算决定**：

1. 超预算 → 发收尾令（`ADJUST` 或 `steer`）：完成当前工具调用后停止，交简短回执；
2. 一个巡检周期后仍未结束 → `STOP`，任务置 `paused`，按最近回执入账；
3. 连回执都没有 → 判定该成员失效，换人重派，备注写清「无回执被停」。

预算落在表里叫「截止」（`oia add --deadline`），巡检第一步 `oia overdue` 就是查它。

`STOP` 不可恢复（Pi 的 `stop` 即杀进程）；要保留上下文用 `interrupt` 之类可恢复的暂停。

## 5. 时序规则

1. **派单即记表**：`subagent` 返回后立即 `oia add --state running`；先记表再回话。
2. **一单一负责人**：后续沟通用 `send_message`，不重开人。
3. **回执即处理**：收到回执的同一轮内完成记账（`oia tick --seen`）与裁决。
4. **验收即归档**：通过就 `archive`；不通过写清条目再返修。
5. **表变即重挂闹钟**：派单/验收/调档后重算 `oia watch`。
6. **用户提问不触发巡检**：只读表回答；要查细节才发 `QUERY`。
7. **一次唤醒最多发 1 个 `QUERY`**，避免刷屏。
8. **待你定 ≤3 条**；超出先解旧的。

## 6. 巡检算法

```
每 T 秒（或闹钟唤醒）：

1. tasks = board 中状态 ∈ {running, blocked} 且 next_check 非空
2. if tasks 为空: 不挂闹钟，结束
3. due = [t for t in tasks if t.next_check <= now]
4. if due 为空: 结束（不应发生，闹钟只在该触发时醒）
5. 对 due 中的任务，按 next_check 升序：
     a. list_agents → 负责人是否在
     b. last_seen 距今 / interval >= 2 → 沉默异常
     c. 有异常 且 本轮的 QUERY 配额未用 → 发 QUERY
     d. 否则 oia tick <ID> --ok
6. `oia tick <ID> --anomaly` 只用于确认异常：节拍回落 30s、加密观察；拿不准就按 `--ok` 记账
7. 重挂 oia watch
```

成本约束：一次唤醒 ≤ 1 次 `list_agents` + 1 次 `oia due` + 最多 1 条 `QUERY`。

## 7. 闹钟契约

`oia watch` 是一个「到点即退出」的常驻进程：

| 情况 | 输出 | 退出码 |
|---|---|---|
| 有任务到期 | `DUE T01,T03` | 0 |
| 没有可巡检任务 | `NO-ACTIVE` | 3 |
| 用法/读表错误 | 错误文本 | 2 |

主控义务：

1. 表一变就换闹钟（停旧的，挂新的）。
2. 会话启动/恢复先 `job_list`，没有闹钟就挂。
3. 闹钟意外退出（退出码非 0/3/被 kill）→ 记一笔异常并重挂。
4. 同时只允许一个闹钟。

`oia watch` 每 2 秒重读一次表，因此新增的短节拍任务最多迟 2 秒生效。

## 8. 失败码

| 码 | 含义 | 谁产生 | 主控动作 |
|---|---|---|---|
| `NO_INPUT` | 缺必要输入 | 负责人 | 补输入或 `ADJUST` |
| `NO_ACCESS` | 无权限/环境不可达 | 负责人 | 换路或升级用户 |
| `SPEC_AMBIGUOUS` | 验收口径有歧义 | 负责人 | 改单重派 |
| `TOO_BIG` | 一单做不完 | 负责人 | 拆单 |
| `CONFLICT` | 与别的任务撞文件 | 负责人 | 串行化或调整范围 |
| `VERIFY_FAILED` | 证据不足/不过 | 主控 | 返修（≤2 次） |
| `STALE` | 超过 2 节拍无回执 | 巡检 | `QUERY`，再超期换人 |

---

## 9. 升级矩阵

| 情形 | 负责人 | 主控 | 用户 |
|---|---|---|---|
| 缺输入 | `BLOCKED` | 补/调 | — |
| 范围外改动 | `DECIDE` | 批/拒 | — |
| 验收口径歧义 | `DECIDE` | 改单 | — |
| 目标变化 | — | 只能上报 | 拍板 |
| 不可逆动作（删/发/花钱/对外） | — | 只能上报 | 授权 |
| 两轮无解 | `BLOCKED` | 上报 | 拍板 |
| 同时 running 已满 | — | 排队 | — |

主控上报格式：**现状一句 → 选项 A/B → 建议 → 不选的后果**。

---

## 10. 归档与历史

- 完成即 `oia archive`，写入：完成时间、产出物、验收结论。
- 归档行**不参与巡检**，`oia due` / `oia next` 跳过。
- 归档区超过 40 行 → 整体移入 `archive/YYYY-MM.md`，表中留指针。
- 只有用户点名才复查归档；需要细节时重开任务或联系原负责人。

---

## 11. 红线

- 不许绕过 `oia` 手改表后不 `validate`。
- 不许把 `review` 说成 `done`；不许自己给自己验收。
- 不许负责人直接找用户。
- 不许嵌套派单。
- 不许在 `waiting_you` / `review` 状态上继续巡检。
- 不许伪造进度、证据、时间戳。
